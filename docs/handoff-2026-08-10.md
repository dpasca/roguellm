## 2. What this session did

Ten commits, `2b235fc..23e1e53`. Two threads.

### Thread A — the reported bug

The player's report: *"I'm in a convenience store, then I move right, and then
from the convenience store I move to some control tower. Then I move right
again and I'm back to the convenience store."*

Two independent causes, both fixed:

1. **Cell types were being generated as unique buildings, then tiled.** The map
   is 80 cells over 4-6 cell types, so each type lands on ~15 cells. The
   prompt explicitly asked for "a specific place from this setting… a server
   room, a rooftop, a loading bay". A World holds one control tower; tiling it
   fifteen times is incoherent under any layout.
2. **Nothing constrained adjacency.** The fallback map was `random.choice` per
   cell — literal white noise — and the model path asked a low-quality model
   for a bare CSV with no validation, falling back to the noise generator on
   any parse failure.

The fix is `docs/region-layer.md`: contiguous areas grown in code, one terrain
each, one backdrop per area, generated crossing prose between adjacent areas,
and a reveal on screen when you cross. Verified in a browser on a real forged
World, not just in tests.

### Thread B — model swap and consequences

`gpt-4.1-mini` → `gpt-5.6-luna` (low tier, effort `high`) and `gpt-5.6-terra`
(high tier, effort `low`). Everything else followed from that: temperature
removal, token accounting, the definition-shape normalizer.

## 3. Decisions that will look arbitrary in the code

Each of these is a place where the obvious reading of the code is not the whole
story.

**Regions are derived, not stored as the source of truth.** `derive_regions`
reads the finished grid back as connected components of equal terrain. Because
region and terrain are 1:1, `map_csv` already determines the regions, so no
schema change was needed for the layout. Only the *crossing prose* is
persisted, because generated sentences are not derivable. If a future change
gives one region several terrains, this inverts and regions must become
authoritative.

**Region count follows terrain count, capped at 6.** The first cut used a fixed
4, which left 1-2 of the forge's 4-6 generated backdrops never displayed —
paid for and unused. One region per terrain means every backdrop earns its
cost.

**Areas have no generated names.** The plan called for them. Skipped: the
terrain name already *is* the area name, and `deployment-handoff.md` already
records the location name appearing three times on one screen. A fourth copy
would worsen a known problem. The crossing lines carried the value.

**The crossing reveal is a subtitle, not a bottom sheet.** The plan said reuse
the encounter sheet. A sheet needs a tap to dismiss and crossings happen 4-8
times a run, so it would tax the single most frequent action. It self-dismisses
in 4.2s and blocks nothing.

**The reveal has two layout modes.** It renders as a banner by default and as a
subtitle over the scene when the World has art. This is not decoration: see
§5.

**Empty crossings are retried once per run, deliberately.** A snapshot with
areas but no crossing lines regenerates them on the next play. The call is
cheap and a World whose crossings were lost to a transient API failure heals
itself rather than staying mute forever.

**The low tier runs at reasoning effort `high`.** Counter-intuitive for a
"cheap" tier, but Luna is cheap enough per token that reasoning is worth
buying, and worldgen quality is the product. Measured: it costs about the same
as `gpt-4.1-mini` did.

## 4. API facts learned by experiment

These were found by running against the real API. None are visible in the code.

**`gpt-5.6` rejects a custom `temperature` unless `reasoning_effort` is
`none`.** Not tier-specific — Terra and Sol accept temperature at effort
`none`, and Luna *rejects* it at effort `low`. It is a 400, not a degradation,
so it takes down every call on the affected tier. Temperature was removed
entirely rather than made conditional; reasoning effort replaced it.

**Model ids** confirmed against `/v1/models`: `gpt-5.6-luna`, `gpt-5.6-terra`,
`gpt-5.6-sol`. Effort levels: `none`, `low`, `medium`, `high`, `xhigh`, `max`.
`gpt-4.1-mini` deprecates **2026-11-04** and rejects the `reasoning_effort`
parameter outright — `resolve_reasoning_effort` strips it so a deployment
still pinning it in `.env` keeps working.

**Reasoning tokens are billed as output and do not appear in the response.**
Prompt and completion lengths alone understate a forge by a third. `gen_ai.py`
now logs `Token usage` per call, ungated by the sensitive-content flag because
counts are not content. Grep a forge's logs for it to remeasure.

**Definition generation returns the right content in the wrong container,
intermittently.** Sampling one call repeatedly gave `list, DICT, list`. Seen
shapes: a bare object instead of a one-element array, an id-keyed mapping, and
the array wrapped under a single key. This killed a forge mid-run with
`KeyError: slice(None, 1, None)`. `normalize_generated_defs` absorbs all three;
the real fix is `response_format`, which is open item 7.

**The cast cap works.** A remeasured forge produced exactly 5 enemies, 5
terrain, 7 items from the samples. An older note about the model returning 11
enemies from a 5-enemy sample is obsolete.

## 5. Traps that cost time

**`.location-stage` is `display: none` without art, and art is off by
default.** `ENABLE_WORLD_ART=0` is the default, so any UI placed inside the
stage is invisible in a default deployment. The crossing reveal was built
inside it and looked correct throughout manual testing — because that testing
used a forged World *with* art. Caught only by code review.

**A test can pass on a hidden element.** The browser test for that feature
asserted `.count() > 0`, which is true for `display: none`. It was green and
wrong. Assert visibility and a non-zero bounding box.

**`git apply --unidiff-zero` silently misplaces hunks.** Used while splitting
commits, it dropped a method into the middle of another one and moved an
assignment into the wrong function. It disables git's context checking, so
there is no error — the tell was deletions appearing in a diff that should
only have contained additions. Use full-context patches and let git verify
placement.

**`@import`ed stylesheets are not cache-busted.** `versioning.js` rewrites
`link[rel=stylesheet]` only. `game.css` used to `@import` five more files,
which kept their cached copies across deploys. Now linked directly from
`game.html`, listed *before* `game.css` to preserve the cascade (an `@import`
sits at the top of its parent).

**Playwright: `networkidle` never fires.** The app holds a websocket open. Wait
on a rendered element instead.

**A 4.2s self-dismissing element cannot be screenshotted through an MCP
round-trip.** Every capture arrived after the fade. Suppressing both the JS
timer and the CSS animation from inside the page is what made it visible.

**Test doubles need updating when `GameState` gains fields.** Adding
`regions` / `region_ids` broke a `SimpleNamespace` fake, and
`initialize_tile_info` swallows the resulting exception and silently produces
degraded prose. That path fails quietly by design; be suspicious of it.

## 6. What verification actually caught

Recorded because it should shape how the next session works, not as
self-congratulation.

- **249 unit tests were green** while every area crossing threw a TypeError.
  The handler had been defined among the `computed` properties instead of in
  `methods`. Only opening the game found it.
- **Code review found the `display: none` bug** *and* that the test written to
  cover it was passing on a hidden element. Neither was visible from the diff
  alone.
- **Reintroducing each bug** to confirm the new test fails is worth the two
  minutes. It was done for the `computed`/`methods` bug, the hidden-element
  bug, and the orphaned-backdrop bug.
- **Forging for real** found the container-shape bug. A green suite never would
  have.

The frontend suite (`tests/test_frontend_smoke.py`) exists because of the
first point. It boots a real uvicorn, seeds a World with a complete snapshot so
no model calls happen, and drives Chromium. Playwright is deliberately not in
`requirements.txt`; the module skips when it or a browser is missing.

## 8. Where to go next

The live list is §14 of `deployment-handoff.md`. Ordered opinion:

1. **The reverse proxy cutover.** Blocks any production deploy and is not a
   code change. `docker-compose.production.yml` no longer joins
   `chatnext3-network` and binds `127.0.0.1:${ROGUELLM_HOST_PORT}`, but the
   shared reverse proxy still resolves RogueLLM by container alias over the
   removed network. **Deploying without repointing it breaks ingress.**
2. **`response_format` on the worldgen JSON calls.** The only open item with a
   confirmed failure behind it (§4). `world_moderation.py` already has the
   pattern, including a fallback for a model that rejects the parameter.
3. **Backdrops at low quality.** One config change, $0.47 → $0.29 per forge,
   measured as visually lossless since they render at 40% opacity behind a
   shade gradient. Worth doing before credits price anything.
4. **Rate limiting on forging.** Needs product decisions first: per-user or
   per-IP, what limit, what the client sees when it trips.
5. **WebP conversion**, then **art in backups** — infrastructure, best batched
   with the deploy work.

Then **Phase 5, credits and payments**, which now has honest numbers to price
against.

Region-layer work that was scoped but not built: nothing blocking. If areas
should ever hold more than one terrain, revisit the two derived-vs-persisted
decisions in §3 first.
